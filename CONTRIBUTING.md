# Contributing

We accept
- Clarifications that improve testability (normative language, definitions)
- Conformance improvements (criteria, checklists, scorecards)
- New catalog controls (AECX-###)
- Profiles for specific protocols (MCP, AG-UI/A2UI, etc.)
- Overlays that harden DAS-1(TM) for regulated environments
- Sanitized worked examples

We reject
- Vendor-specific requirements in the core spec
- Non-testable language in normative sections

PR requirements
- State whether the change is normative or informative
- State conformance impact
- Update spec/core/changelog.md
